## 3️⃣ 2개 프로모션 코드 등록

콘솔 등록은 2개만 진행. 빙수 4티어 보상은 단일 코드(`BINGSU_REWARD`)로 통합하고,
실제 지급 금액은 클라이언트의 `generateReward(tier)`가 BM_DESIGN.md 분포에 따라
변동 지급 (1~1,000원). 각 코드별로 테스트 호출 1회 필수 (토스 앱 QR로).

| 프로모션 코드 | 미션명 | 한도 (1회 지급) | 1인 한도 (1주) | 비고 |
|-------------|------|---------|---------|--------|
| `BINGSU_DAILY`  | 오늘의 빙수 출석 선물 | 1,000원 | 5,000원 | 1회/일 |
| `BINGSU_REWARD` | 빙수 만들고 보상받기 | 1,000원 | 5,000원 | 4티어 공통, 평균 10.65원 |

### 프로모션별 마케팅 문구 (혜택 탭 노출)

1. **BINGSU_DAILY**:  "🎁 매일 한번 광고 보고 출석 선물 1원!"
2. **BINGSU_REWARD**: "🍧 빙수 만들고 최대 1,000원!"

## 4️⃣ 광고 ID 발급 (콘솔에서)

콘솔에서 "광고 관리"에서 발급:

| 광고 유형 | 용도 | 형식 |
|----------|------|------|
| 전면 광고 (Interstitial) | 빙수 만들기 단계 진행 | `ait.???-interstitial` |
| 배너 광고 | 메인 화면 하단 | `ait.???-banner` |

발급받은 ID는 **`src/constants/adConfig.ts`** 에 입력 (Claude 작업).

## 5️⃣ 비즈월렛 충전

- **최소**: 30만원
- **권장**: 30만원으로 시작 → 운영 데이터 보고 추가

일일 BM:
- 광고 수익 ₩131
- 보상 지급 ₩108
- **순이익 ₩+23 (수익률 18%)**

30만원이면 약 277일치 운영 가능 (이론상). 실제로는 사용자 수에 따라 다름.

## 6️⃣ 검수 제출 시 첨부 자료

### 정확도 검증
- 단위 테스트 100,000회 통과 (`src/utils/__tests__/`)
- 0원 보상 발생 0회
- 확률 공시 (`/probability-info` 화면)

### 도박 방지
- 금지어 ("당첨/추첨/복권/꽝/도박") 사용 X — 단위 테스트로 검증
- 모든 빙수에 보상 보장 ("0원 보상은 절대 없어요!" 명시)

### 정보 보호
- 외부 서버 통신 X (모든 상태 AsyncStorage 로컬 저장)
- 개인정보 수집 X (토스 식별자만 사용)
- 개인정보 처리방침 = `/policy` 화면에 명시

### 사용자 보호
- 인트로 모달 (첫 사용자 안내)
- 하루 10그릇 상한
- 출석 선물 1일 1회
- `getServerTime` 기반 일일 리셋 (시간 조작 방지)

## 7️⃣ 검수 응답 표준 답변

검수에서 자주 묻는 질문 + 답변 미리 준비:

### Q1. 도박/사행성 아닌가?
**A**: 
- 빙수 만들기는 광고 시청 횟수에 비례한 단순 보상 시스템
- 4티어 등장 확률은 60/25/10/5로 공개 (`/probability-info`)
- 0원 보상 절대 없음 (단위 테스트 검증)
- "당첨/추첨/복권" 등 도박 단어 사용 X

### Q2. 카테고리가 비게임인 이유?
**A**: 
- 게임적 요소 (점수, 승패, 경쟁) 없음
- 단순 광고 시청 → 보상 모델
- 추억 음식 만들기 컨셉의 캐주얼 콘텐츠

### Q3. 미성년자 보호 대책?
**A**: 
- 도박 단어 사용 X
- 가족/연애/부정 감정 메시지 X (모든 메시지 검증됨)
- 일일 상한 설정 (10그릇 + 출석 1회)

### Q4. 보상 지급 안정성?
**A**: 
- `grantPromotionReward` SDK 사용 (앱인토스 표준)
- 에러 코드별 안내 메시지 (4109/4110/4112 등)
- 광고 실패 시 폴백 처리
