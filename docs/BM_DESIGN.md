## 수익 구조

```
유저 행동: 광고 시청
    ↓
앱인토스 광고 수익 (₩1.3/회)

    ↓
프로모션 예산으로 토스 포인트 지급
```

## 2개 프로모션 코드

> 콘솔 등록 단순화를 위해 빙수 4티어 보상은 단일 코드(`BINGSU_REWARD`)로 통합.

| 코드 | 용도 | 한도 | 미션 이름 | 평균 |

## 일일 수익 시뮬레이션

```
출석 선물:  광고 1개  → 보상 1원
빙수 10그릇: 광고 100개 → 보상 106.5원
────────────────────────────────
합계: 광고 101개, 보상 107.5원

광고 수익:  101 × ₩1.3 = ₩131.3
보상 지급:  ₩107.5
────────────────────────────────
순이익: ₩23.8 (수익률 18%)
```

## 전체 회당 기댓값
```
0.60 × 5.57 + 0.25 × 10.47 + 0.10 × 21.33 + 0.05 × 51.18
= 3.34 + 2.62 + 2.13 + 2.56
= 10.65원
```

## 📊 새 앱인토스 정산 정책 기반 재검증 (2026-05-25)

> 위 일일 시뮬레이션은 광고 1개당 ₩1.3을 단순 수익으로 가정했으나, 새 정산 정책을 적용하면 운영비·수수료·부가세를 모두 거쳐야 함. 아래에서 재산출.

### 정산 흐름

```
광고 매출 (₩X)
  ├─ -30% 외부 미디에이션/토스 애즈 운영비
  └─ 광고 수익 (₩X × 0.7)
        ├─ + 광고 수익 부가세 10%
        ├─ - 앱인토스 수수료 15% (광고 수익 기준)
        ├─ - 앱인토스 수수료 부가세 10%
        └─ = 파트너사 정산금
              └─ - 비즈월렛 토스 포인트 지급 (무상, 부가세 X)
                    = 순이익
```

⚠️ **2026-04-30 종료된 토스 수수료 0% 프로모션은 적용 불가** — 현재는 15% 그대로.

### 핵심 모호점 — ₩1.3이 매출인가 수익인가

기존 BM 문서의 광고 단가 ₩1.3이 "광고 매출 단가"인지 "운영비 차감 후 광고 수익"인지에 따라 결과가 크게 갈림.

#### 사용자 1명/일 (광고 101개, 보상 ₩107.7) 두 시나리오 비교

| 항목 | 보수적 (₩1.3 = 매출) | 낙관적 (₩1.3 = 수익) |
|---|---:|---:|
| 광고 매출 | ₩131.3 | ₩187.6 |
| -30% 외부 운영비 | -₩39.4 | -₩56.3 |
| **광고 수익** | **₩91.9** | **₩131.3** |
| +광고 수익 부가세 10% | +₩9.2 | +₩13.1 |
| -앱인토스 수수료 15% | -₩13.8 | -₩19.7 |
| -수수료 부가세 10% | -₩1.4 | -₩2.0 |
| **파트너사 정산금** | **₩85.9** | **₩122.7** |
| -비즈월렛 보상 지급 | -₩107.7 | -₩107.7 |
| **순이익/일/명** | **−₩21.8 (-25%)** | **+₩15.0 (+14%)** |

### 흑자 전환을 위한 옵션

| 옵션 | 효과 | 리스크 |
|---|---|---|
| A. 출석 선물 (이미 1원 고정 적용) | -₩2/일/명 (이미 반영됨) | 정책상 더 줄이기 불가 |
| **B. 보상 분포 전체 -20%** | **±₩0 부근, 흑자권 진입** | CLAUDE.md "BM 수치 변경 금지" 위반 |
| C. 광고 횟수 줄이기 | 수익은 더 감소 | NG |
| D. 토스 0% 프로모션 활용 | 적용 불가 (2026-04-30 종료) | - |

### 권장 액션

1. **샌드박스 운영으로 실 eCPM 확인** — ₩1.3이 매출인지 수익인지 콘솔의 "광고 매출" vs "광고 수익" 컬럼으로 확정. 위 두 시나리오 중 어느 쪽이 맞는지 결정.
2. **첫 1주 운영 후 실제 정산 데이터로 재산출** — eCPM은 시즌·광고주에 따라 ±30% 변동 가능.
3. **DAU·전체 마감률·재방문율**을 누적 확인 후 BM 수치 재조정 필요 여부 판단.
4. 만약 보수적 시나리오 (현재 -25%)가 확정되면, **현재 BM 수치 변경 금지 규칙을 한 번 깨고 외부 정책 변화에 따른 재조정 필요** — 그 시점에 사용자 협의 후 옵션 B 적용 검토.
